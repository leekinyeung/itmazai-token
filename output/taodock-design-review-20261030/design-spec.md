# Taodock 全站统一设计规范确认稿

版本：0.1　日期：2026 年 10 月 30 日　状态：待视觉确认

这套规范覆盖官网首页、模型广场、控制台、列表、表单、钱包、设置及通用反馈。整体方向是清晰、克制、有品牌识别的开发者工具：以中性色建立秩序，以蓝色强调操作，以稳定的排版和间距支撑高密度信息。官网与控制台共享字体、颜色、圆角和控件语言，分别采用展示型和工作型布局。

确认范围为视觉语言、信息层级、组件尺度和页面骨架。配套效果图是设计预览，图中统计值均为演示数据；实际数据、模型、价格、权限和服务可用性由既有业务配置决定。

## 设计原则

1. **先表达任务。** 每个页面有明确标题和主要操作；查看数据、检索记录、创建资源各有清晰入口。
2. **先用排版分组。** 通过留白、对齐和分隔线组织内容；独立对象和独立任务才使用卡片，避免连续嵌套卡片。
3. **颜色具有固定含义。** 蓝色用于主要操作、选中和链接；绿、橙、红用于成功、警告和错误。模型厂商品牌色保留原有含义。
4. **整体一致，密度适配任务。** 首页强调理解与接入，后台强调扫描与操作；两者使用同一视觉基础。
5. **以内容适应语言。** 中文、英文及其余支持语言共用布局规则，长文案能够换行，重要操作不因翻译变长而被截断。

## 品牌与图形

- 品牌名称采用 `TaoDock`，使用现有站点配置和现有标识，不在本次改版中重新设计 Logo。
- Logo 与文字水平排列，常用标识尺寸 24 或 28 px，间距 8 px；尊重管理员配置的品牌名称和 Logo。
- 界面操作图标统一采用项目已安装的 Hugeicons，标准尺寸 18 px，辅助图标 16 px，较大入口 20 px。厂商标识复用现有品牌图标库。
- 官网可沿用现有模型生态插画，限制在介绍区域；图像保持原始比例，并在深色主题中单独处理背景和对比度。
- 装饰渐变仅用于首页插画或局部品牌展示。操作控件、后台表格和正文区域保持平整、稳定的表面。

### 对比度基线

按不透明 sRGB 色值计算，浅色正文对白色约 16.22:1，次级文字对白色约 5.57:1、对页面底色约 5.24:1，主按钮白字对蓝底约 6.70:1。深色正文对内容表面约 15.08:1，次级文字约 7.80:1。

这些计算只覆盖表中的静态组合。实现时仍须检查悬浮、选中、禁用、透明叠加、图表及图片背景上的真实组合。普通正文最低 4.5:1，大字号文字最低 3:1。[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

必要的控件边界和状态指示与相邻背景至少达到 3:1；表中的浅色输入边界对白色约 3.51:1，深色输入边界对内容表面约 4.90:1。装饰分隔线不能承担唯一的控件或状态识别作用。[WCAG 非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 字体与信息层级

沿用项目已安装的 Public Sans。中文使用系统无衬线回退；代码和技术标识使用项目现有等宽字体。正文最多使用一套无衬线字体族及一套等宽字体族。

建议字体栈为 `Public Sans Variable, PingFang SC, Microsoft YaHei, Noto Sans CJK SC, sans-serif`，其中中文字体按设备可用性回退，不新增远程字体请求。

| 层级 | 桌面字号与行高 | 字重 | 使用范围 |
| --- | --- | --- | --- |
| 官网主标题 | 56 / 64 px | 600–700 | 首页首屏，窄屏降为 36 / 44 px |
| 官网区块标题 | 28 / 38 px | 600 | 模型入口、接入说明 |
| 后台页面标题 | 28 / 36 px | 600 | 页面顶部 |
| 分区标题 | 18 / 28 px | 600 | 图表、表单分区 |
| 卡片标题 | 16 / 24 px | 600 | 独立内容单元 |
| 正文与表单 | 14 / 22 px | 400 | 桌面工作界面 |
| 移动端正文与输入 | 16 / 24 px | 400 | 移动阅读和输入 |
| 辅助说明 | 12 / 18 px | 400 | 次要提示、图表刻度 |
| 关键指标 | 30 / 38 px | 600 | 概览指标，不作为正文样式 |

金额、用量和表格数字使用等宽数字，数值列右对齐。金额和额度沿用现有格式化与精度语义；视觉改版不改变单位、币种、换算和计费口径。界面语言进入 Intl 前继续通过 `toIntlLocale` 转换。

## 空间与页面骨架

间距基于 4 px 网格，常用值为 4、8、12、16、24、32、48、64 px。页面和组件通过这一套尺度组合；特殊图像定位可使用独立值，但不扩散为通用尺寸。

| 项目 | 统一值 |
| --- | --- |
| 全局导航高度 | 64 px |
| 展开侧栏宽度 | 232 px |
| 折叠侧栏宽度 | 64 px |
| 桌面内容边距 | 常规 24 px，宽屏 32 px |
| 移动内容边距 | 16 px |
| 主要区块间距 | 24 px |
| 区块内部间距 | 16 px |
| 卡片内边距 | 标准 24 px，紧凑 16 px |
| 官网内容最大宽度 | 1280 px，居中 |
| 后台常规内容最大宽度 | 1440 px；高密度数据页按可用宽度展开 |
| 长表单主体最大宽度 | 800 px |

后台统一使用“页面标题与说明 → 主要操作 → 筛选或分区导航 → 内容 → 分页或提交”的顺序。面包屑只在确有层级时出现。标题和操作区域保持稳定位置，不随数据加载跳动。

顶部导航、侧栏和内容层各有明确边界，避免把整站套进带厚阴影的大卡片。常规面板使用边框或分隔线，相关统计可合并为一个指标条。

## 圆角与层次

基础 `--radius` 定为 12 px，继续使用项目已有的派生圆角机制。对应比例约为：`sm` 7.2 px、`md` 9.6 px、`lg` 12 px、`xl` 16.8 px。控件使用 `rounded-md`，主要面板使用 `rounded-xl`，不再为每个页面分别定义同类圆角。

标签圆角用 `rounded-sm`；头像、状态点及明确的分段控件可以使用全圆角。普通按钮、输入框、列表容器保持统一矩形比例。

常规卡片使用 1 px 边框，默认无投影。菜单可使用 `0 8px 24px rgb(15 23 42 / 10%)`，弹窗可使用 `0 16px 48px rgb(15 23 42 / 16%)`。深色模式通过更明确的表面和边界分层，投影仅作辅助。

后台静态卡片保持位置稳定；可点击卡片通过边界和背景反馈可操作性，官网展示卡片可有轻微悬浮反馈。

## 公共组件

### 按钮与控件

| 规格 | 高度 | 用途 |
| --- | --- | --- |
| 紧凑 | 36 px | 桌面工具栏、表格操作 |
| 标准 | 40 px | 常规按钮、输入、选择器 |
| 舒适 | 44 px | 首页行动入口、移动主要操作 |

图标按钮与同规格控件等高、等宽。移动端触控目标按至少 44 × 44 px 设计，图形可以更小。桌面密集区域的较小控件须满足适用的最小目标或间距规则；WCAG 2.2 AA 的目标尺寸基线是 24 × 24 CSS px，并有明确例外。[WCAG 目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

- 主按钮为品牌色实心，表达页面主要操作；次按钮为轮廓或中性填充，行内操作使用文字或图标按钮。
- 删除、停用等危险行为使用危险变体与既有确认组件，保留现有业务确认规则。
- 控件提供 default、hover、focus-visible、active、disabled、loading、invalid 状态。加载时保留宽度并展示进度反馈。
- 表单标签放在控件上方，标签与控件间距 8 px，字段间距 20 或 24 px；帮助说明和错误位于对应字段下方。
- 错误状态同时提供图形或边界与文字，不能只靠红色表达。
- 复制继续使用 `CopyButton`，确认继续使用 `ConfirmDialog`，弹窗复用既有布局与底部操作区域。

### 列表与表格

- 复用现有 `DataTablePage` 和共享表格体系；筛选器在表格上方集中排列。
- 表头高 44 px，普通数据行至少 52 px，紧凑单行记录可为 44 px；多行内容按内容自然增高。
- 文本左对齐、数字右对齐，重要标识与次要说明有稳定层级。状态标签保留文字。
- 默认使用细行分隔和轻微悬浮底色，选中状态使用独立的低饱和底色及复选框。
- 日期、模型、用量等筛选放在第一层；低频选项进入可展开的高级筛选，不挤压主要搜索入口。
- 分页保持在内容底部，展示总条数、每页数量和当前页；移动端保留必要操作。
- 窄屏优先使用既有移动列表布局；确需保留横向列结构时，仅表格区域水平滚动。
- API 标识按既有脱敏规则展示，长标识有复制入口；效果图只使用占位符，不包含可用凭据。

### 弹窗与抽屉

弹窗使用内容驱动的高度，典型宽度 480、640、800 px；复杂编辑在足够宽度内进行，移动端按照内容转为近全屏弹层或既有抽屉。标题、正文和操作区有固定层级，滚动发生在正文区，关闭与提交在安全区域内可达。

焦点进入、退出、键盘操作和滚动锁定复用现有组件行为。视觉变体通过兼容的 props 或公共样式扩展表达。

## 页面类型

### 官网首页

以“理解平台 → 浏览模型 → 获取 API Key”为主线。首屏使用左侧清晰标题与主要接入操作、右侧现有模型生态视觉。主按钮为“获取 API Key”，次入口为“浏览模型”。随后展示厂商或能力入口，再提供统一接口地址与文档入口。

标题、正文和插画各自占有明确空间。展示型布局使用更充足留白，避免多处装饰与介绍竞争。模型是否可用及具体价格以实际配置为准。

### 控制台与数据概览

以“判断运行情况 → 查看趋势 → 进入记录或管理”为主线。指标条承载不超过四个关键指标；图表是主要内容，必要的余额、服务状态或模型分布作为辅助。新用户接入指导可以根据既有状态展示并允许收起。

管理功能沿用实际权限和导航分组；设计图仅表现用户可见的入口，不预设新增业务能力。

### 使用日志与管理列表

以“定位记录 → 比较字段 → 查看详情”为主线。标题、日期与关键筛选、统计摘要、记录表格和分页由上到下排列。金额和用量保持原精度，耗时和状态有明确文字，不把每个数据单元都包装成彩色徽章。

### 设置与长表单

以分组标题、说明、字段和统一保存区域组织。字段宽度按输入内容选择，避免所有字段铺满宽屏。关联选项同组展示，复杂说明复用已有提示组件。保存、失败和未保存状态在整个设置区采用一致的反馈方式。

### 模型广场与钱包

模型广场共享搜索、筛选和对象卡片结构；提供方标识、能力、真实价格和接入操作各有稳定位置。钱包将余额、充值或订阅与历史记录分区展示；沿用业务已有币种、支付状态和金额精度。

## 图表与数据展示

浅色图表顺序采用蓝 `#1D4ED8`、青 `#0E7490`、紫 `#7C3AED`、橙 `#B45309`、绿 `#087A55`；深色相应采用 `#93B4FF`、`#67D4E8`、`#C3A6FF`、`#F3C36B`、`#6CDEAA`。

颜色与系列的映射在同一工作区内保持一致；状态色和类别色依靠位置、图例和文字区分含义。多序列增加线型、标记或直接标签，不能仅依赖颜色。

柱状图数值轴原则上从零开始；必要的折线局部范围明确标注。标题、日期范围、单位和图例齐全，网格线弱化，悬浮提示保留完整单位与精度。无数据使用明确空状态，不使用看似真实的默认曲线。

## 响应式与可访问性

- 小于 768 px：16 px 页面边距，侧栏使用抽屉，主要操作触控尺寸 44 px，筛选分行或进入筛选面板，指标两列或单列，表格使用已有移动适配。
- 768 至 1199 px：以折叠侧栏释放空间，复杂双栏内容可改为单栏，工具栏允许自然换行。
- 1200 px 及以上：展开侧栏，常规内容采用 24–32 px 边距；有明确主次关系的页面才使用双栏。
- 最小复核宽度 375 px；验证 390、768、1024、1440 px 以及 200% 浏览器缩放下的内容可达性。
- 焦点使用清晰的 2 px 轮廓与 2 px 偏移，不能只依赖模糊阴影。控件名称、标签、状态与视觉保持一致。
- 浅色与深色分别定义和验证；深色使用独立表面层级，不用整页反色代替设计。
- 文本、布局及辅助技术名称沿用项目 i18n 流程；英文、法文和俄文长文案不得挤压主要操作。

## 动效与反馈

颜色与边界过渡 150 ms，菜单和轻弹层 180 ms，页面内容出现最多 220 ms。优先使用 opacity 和小幅 transform，不以大范围缩放、位移或循环闪烁装饰工作界面。

支持 `prefers-reduced-motion`，关闭非必要位移和循环动效。加载使用尺寸稳定的骨架或现有加载组件；空状态给出解释和一个相关操作，错误状态提供现有重试路径。保存、复制、筛选和导出继续使用项目统一反馈方式。

## 工程落点与维护

视觉确认后按以下顺序实施：

1. 将本文经确认的约束写入 `web/AGENTS.md` 或其明确引用的规范入口，定义后续开发责任。
2. 在 `web/src/styles/theme.css` 更新语义变量和 Tailwind 映射；在 `theme-presets.css` 处理预设覆盖。沿用 CSS 变量作为统一主题来源。[shadcn 主题机制](https://ui.shadcn.com/docs/theming)
3. 在 `theme-customization.ts` 明确新版默认值；显式保存的用户偏好继续按既有规则解析，迁移或重置偏好须单独决定。
4. 在 `components/ui/`、共享业务组件和布局入口统一尺寸、变体、间距与状态。优先复用 `CopyButton`、`ConfirmDialog`、共享弹窗、`SectionPageLayout`、`DataTablePage` 和既有状态组件。
5. 先完成首页、概览和一类列表作为样板，再迁移设置、模型广场、钱包及其余页面；将写死的品牌蓝、独立阴影和重复控件样式收敛到公共定义。
6. 对变更涉及的响应式、交互和状态补充必要回归，运行受影响测试、类型检查、文件 lint 和生产构建，再进行浅深主题与多语言视觉检查。

## 确认项目

请重点评估这四项：品牌蓝和中性色是否符合产品气质；字号与页面密度是否易读；控件和卡片形状是否合适；首页与控制台是否能被识别为同一个产品。
