# 会话兜底重试

故障兜底是现有会话重试流程的最后一步：OpenAI Chat Completions、Claude Messages 或 Gemini generateContent 的正常重试次数用完后，系统从管理员配置的有序目标池中选择第一个符合请求能力的渠道和模型，再调用一次。兜底调用无论成功或失败都不会继续重试。

功能默认关闭，不改变普通重试、渠道调度和用户计费。旧版 Completions、Responses、图片、Embeddings、Rerank、音频、视频、Realtime 和异步任务不使用此功能。

## 后台配置

入口为“请求策略 → 故障兜底”。后台只需要配置三项：

1. 添加一个或多个兜底目标，并为每个目标选择具体渠道和该渠道中的模型。
2. 使用上移、下移按钮调整检查顺序。
3. 打开“启用模型兜底”并保存。

兜底执行不依据用户分组、渠道优先级或权重重新选择渠道，始终按后台顺序检查配置中的精确渠道。能力不匹配、渠道停用或没有可用 Key 的目标可以在实际调用前跳过；一旦选中目标并开始真实上游调用，本次兜底即消耗完毕，失败后不会尝试池中的下一个目标。渠道自身的模型映射和多 Key 选择仍然生效，但真实调用失败后不会换 Key 重试。无需额外配置协议、验证、并发、速率、超时、成本或重试次数。

选中的模型需要具备完整能力元数据，渠道必须启用且确实配置了该模型。显式空能力数组 `[]` 表示可用于基础文本会话；能力字段缺失、无效或已停用时不能启用兜底。

## 能力匹配

系统从本次请求体识别实际需要的能力，并检查指定的兜底模型是否覆盖全部能力：

- 流式请求：`streaming`
- 非空工具或函数定义：`tool_calling`
- JSON Object：`json_object`
- JSON Schema：`json_schema`
- 图片输入：`image_input`；多张图片同时要求 `multi_image`
- 显式推理参数：`reasoning`

例如，一个同时包含图片、工具和流式输出的请求，候选模型必须同时声明 `image_input`、`tool_calling` 和 `streaming`。系统会跳过能力不匹配的目标并检查下一个目标；包含音频、视频等未支持媒体时，整个请求不进入兜底。

## 触发条件

兜底只在以下条件同时满足时触发：

- 请求属于支持的会话接口；
- 正常重试因重试次数用完而结束；
- 客户端仍连接，并且尚未提交任何响应；
- 目标池中至少存在一个渠道已启用、模型存在且能力匹配的目标。

业务错误、固定渠道、严格会话绑定、客户端取消或已经开始向客户端输出的流式请求不会追加兜底重试。所有目标均不可用时返回原错误；真实兜底调用报错时返回兜底错误，不切换渠道、模型或 Key 再次调用。

## 配置接口

配置使用 schema v6，并通过 `base_revision` 防止并发覆盖。目标数组顺序就是检查顺序，最多 20 个且不允许重复：

```json
{
  "schema_version": 6,
  "base_revision": 12,
  "document": {
    "settings": {
      "enabled": true
    },
    "targets": [
      {
        "channel_id": 18,
        "model": "claude-sonnet"
      },
      {
        "channel_id": 21,
        "model": "gpt-4.1-mini"
      }
    ]
  }
}
```

接口只接受并加载 schema v6；旧版试验配置不再参与运行，请直接在当前页面重新保存最终配置。

## 计费与日志

用户账单始终使用原请求模型、原用户组、折扣和价格快照。兜底模型价格不参与用户结算，整次请求仍只有一次预扣和一次结算或退款。

管理员日志记录原模型、请求所需能力、目标池快照、跳过原因、实际渠道和映射后的上游模型，便于排查；普通用户日志继续使用原公开模型。
